## Objetivo e escopo
Auditoria e validação contínua da postura de segurança, isolamento multitenant, integridade de assinaturas HMAC SHA-256, proteção contra ataques de repetição (replay), expiração/revogação de credenciais e garantia de ausência de vazamento de segredos em logs e respostas da API.

## Entrega
- Arquivos alterados / criados:
  - `tests/authorization-audit.test.ts` (suíte com 5 cenários completos cobrindo cross-tenant isolation, tamper, replay, expiração, revogação e sanitização de logs)
  - `docs/evidencias/SEGURANCA/README.md` (relatório técnico consolidado da auditoria de segurança)
  - `docs/entregas/RB-068.md` (este documento de entrega)
- Decisões relevantes:
  - Utilização de banco de dados SQLite isolado por execução de teste com schema oficial via Prisma migrate deploy.
  - Verificação assíncrona de streams de log para garantir que segredos como `signing_secret` e chaves AES-256 nunca sejam expostos em saídas de auditoria.

## Como conferir
### Preparação
Certifique-se de que as dependências estão instaladas e o Prisma Client gerado:
```bash
npm install
npm run db:generate
```

### Passos
1. Execute o teste de auditoria de autorização e isolamento:
   ```bash
   node --import tsx --test tests/authorization-audit.test.ts
   ```
2. Execute todos os testes de segurança do repositório:
   ```bash
   node --import tsx --test tests/credentials.test.ts tests/signed-request.test.ts tests/tenant-isolation.test.ts
   ```
